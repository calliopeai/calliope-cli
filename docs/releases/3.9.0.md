# Calliope CLI 3.9.0

Embedded headless clients can pause, resume and steer the original live turn
through the public `RuntimeControl` API. Pause is acknowledged only after a saved,
quiescent checkpoint and the host's optional acknowledgment. Resume requires that
exact receipt. Ordered, idempotent steering is saved before the next model request.

The original session, cumulative usage, budget, iteration allowance and deadline
remain in force. Cancellation still ends a paused wait. Permission checks remain
active after resume; a revoked policy can refuse the next tool. Failed checkpoint
writes, stale conversation revisions and refused host acknowledgments halt control
admission without an automatic retry.

An unanswered question can be parked while paused. An answer arriving during the
pause waits before changing the saved conversation. Already-saved question receipts
retain their revision until the host acknowledges them.

Hosts can also verify a proposed completion against external acceptance evidence.
With `completionCheck`, failed criteria return bounded feedback to this same
conversation. An accepted result identifies the saved proposal and host evidence
hash in the JSONL completion receipt. The original iteration, check, cost and time
limits still apply; steering during verification invalidates its acceptance.
Old SDKs can be refused before inference by checking the exported
`COMPLETION_CHECK_PROTOCOL_VERSION` capability.

See [the runtime contract](../runtime.md) for the public SDK example and host
responsibilities. This API controls one live turn. Factory chat controls, durable
host intents, retained CLI homes and fenced process recovery need their own host
integration. It does not add terminal slash commands or move account credentials.

Node 24 or later remains required. Native binaries are released separately after
their platform signing, notarization and smoke gates pass.

Refs: #518, #520.
