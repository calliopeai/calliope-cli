# Calliope CLI 3.12.0

Reviewed reasoning effort for native OpenAI Responses and host-admitted recovery
of an original quiescent turn.

- Native OpenAI reasoning effort follows the existing Responses protocol selector.
  An exact, expiring version-2 operator profile can supply documented effort values
  when live discovery omits them. Discovery must still confirm the model; explicit
  live rejection wins. Routing labels reviewed evidence and dispatch rechecks the
  profile, endpoint and discovery before each request, including tool continuations.
- Preserve boolean effort rejection from discovery alongside structured capability
  metadata. Unsupported adapters, absent evidence, profile changes and expiry stop
  inference without discarding an existing reservation.
- Trusted hosts can opt into the versioned original-turn recovery API for a retained
  quiescent checkpoint. Recovery preserves the original session, consumed counters,
  completion allowances, deadline and ledger instead of issuing a fresh allowance.
  Missing, stale or rejected host admission stops execution.

Hosts still qualify ownership, checkpoints and original ledger continuity before
replacement execution. These SDK contracts do not implement an automatic physical
worker replacement. Upgrade validating ledger hosts alongside workers before using
`reasoningEfforts`; older SDKs reject proofs containing the new field. Existing billing profiles and historical journal hashes remain
valid; API estimates remain distinct from invoice charges and missing usage stays
unknown.
