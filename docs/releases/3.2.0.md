# Calliope AI CLI 3.2.0 release preparation

Status: **release candidate; xAI explicitly deferred**. The package version is
prepared for 3.2.0; publication is performed by the tagged release workflow.
The strict gate requires real evidence for every configured provider and permits
only the explicitly declared `CALLIOPE_RELEASE_DEFERRED_PROVIDERS` set; xAI is
currently unavailable and remains visible as unavailable in readiness reports.

The foundation shares turn execution and permissions across terminal, headless
and ACP, propagates cancellation, loads trusted scoped instructions, preserves
Bedrock reasoning state and uses Google's `@google/genai` SDK. DeepSeek, xAI and
Cerebras use provider profiles; AI21 is retired. The conformance suite exercises
the installed SDKs through intercepted HTTP and separately replays real captures.

This release preparation corrects the active conformance matrix, adds an offline
machine-readable readiness inventory, and bounds live probes with persistent
dollar reservations. Strict model discovery exposes failed requests instead of
reporting emergency fallbacks as current provider evidence.

REPL controls add live provider/model validation, health and discovered metadata
in pickers, session-only switching, `/once` turn overrides, and `/defaults` for
trusted project preferences. CLI invocation flags and ACP share the same
preference resolution; queued messages keep independent choices. See
[Model preferences](../model-preferences.md).

The provider health layer adds local observations, `/doctor` and headless JSON
diagnostics, bounded discovery probes, and quarantine with explicit recovery.
See [Provider health](../provider-health.md) for the schema, metric definitions,
retention, CI import/export, and recovery procedures.

## Validation commands

```sh
npx tsc --noEmit
npm test -- --maxWorkers=2
npm run test:coverage -- --maxWorkers=2
npm run test:conformance
npm run test:conformance:release
npm run build
npm run bench
node scripts/conformance/report.mjs --json --require-ready
```

Publication is conditional on current passing evidence, clean install/headless
smokes, a secret-free clean git tree, green CI and the applicable approval gates.
Never bypass `prepublishOnly` to work around missing captures.

Session recovery now uses bounded, private snapshots with explicit revisions
and preserves tool/reasoning metadata at runtime checkpoints. `/new`, `/sessions`
and validated `/resume` support separate terminals and interrupted work; see
[recovery procedures](../session-recovery.md).

Recorded session history adds `/branch`, `/checkout`, `/diff`, `/replay`, private
`/export` and `/import`, and `calliope session ... --json`. Terminal, headless and
ACP save a safety branch before the first allowed risky action of each turn;
replay never executes recorded tools. See [session history](../session-history.md)
for schema, limits, policy enforcement and recovery boundaries.

Terminal permission dialogs show the full target and risk reason, queue parallel
requests, and offer bounded approvals for exact file operations. Project grants
survive restart; session grants remain in memory. `/permissions` and `calliope
permissions --json` inspect or revoke them, and every use rechecks current gates.
ACP maps its session approval option to the same grant contract. See
[permission decisions and schema](../permissions.md).

Streaming retries now replace failed partial text in the terminal and stop
append-only clients after a partial failure. Separate tool progress and bounded
private output records support `/tools` inspection, resizing, restart and
session transfers. Headless turn JSON remains stable; `calliope session outputs`
adds read-only inspection. See [streaming semantics and schema](../streaming.md).

The first orchestration layer adds strict plan contracts, hierarchy/dependency
validation, artifact provenance declarations, and private run preparation with
CLI/REPL status, review, cancellation and replay. Preparation remains inactive;
explicit execution runs bounded workers and records independently checked
artifact evidence. See [orchestration preparation](../orchestration.md) and
[coordinator execution](../coordinator-execution.md). Synthetic execution tests
are distinct from the still-missing real-provider certification evidence.

`calliope orchestrate` and `/orchestrate` now connect goal decomposition to that
coordinator. Planning is read-only, proposals carry provenance and inference
markers, and execution requires approval of the current hash. One durable goal
envelope covers planning plus execution; cancellation, recovery and direct linked
run commands preserve the original allocations, deadline and unknown charges.

## Project brain

`calliope brain` and `/brain` add local source ingestion, SQLite search, typed
knowledge graphs, human review/reversal, stale-source detection and private
transfers. `/kg search|graph` provides graph aliases. `brain ingest-run` links
verified executor evidence and proposed improvement hypotheses without model
requests or imported authority. See [project brain](../project-brain.md) for
commands, schemas, limits, safety boundaries and recovery.
