# Calliope CLI 3.8.1

This patch makes generic headless reasoning effort explicit and distinguishes
missing provider usage from reported zero in the execution journal.

## Headless reasoning effort

Use `--reasoning-effort medium` or `CALLIOPE_REASONING_EFFORT=medium` for headless
execution. The flag overrides the environment default. Missing, invalid and
duplicate flag values exit 2. The shared runtime retains the selected effort
through model requests and tool continuations; existing live provider/model
capability and protocol checks refuse unsupported effort rather than silently
using a default. Calls without an effort keep their previous behavior.

Node and native artifact smoke tests exercise the actual SDK request against a
synthetic local Anthropic transport, including a real file-tool turn. They verify
effort forwarding and refusal before model dispatch when metadata does not
confirm support. This is packaging/transport qualification, not evidence of live
account eligibility or a completed paid factory run.

## Usage presence

Assistant journal events now include optional `usageReported`. `false` means the
provider omitted usage even if legacy numeric counters are zero; `true` preserves
a genuinely reported zero. Consumers must retain unknown telemetry as unknown
and keep subscription consumption separate from API estimates and actual charges.
Older journals without the field remain readable.

## Remote admission deadlines

A remote task admission that expires in transport now returns the typed deadline
refusal, matching a deadline reached before dispatch. Authorization and parent
budget bounds still apply first; an expired request allocates no execution slot
or budget charge. A deterministic HTTP regression covers this boundary.

Node 24 or later remains required. Experimental subscription integrations retain
their existing limitations; this patch does not qualify a remote subscription
factory route or provision accounts, mailboxes, credentials or grants.
