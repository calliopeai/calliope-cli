# Calliope CLI 3.5.0

One parent execution allowance can now be shared with children running in other
processes or on other hosts. A parent serves its run's existing reservation
ledger over `delegation-ledger/v1` (`calliope ledger serve`), and children
reserve and settle against it with tokens scoped to their own accounts.

The ledger stays the only authority: requests are charged before dispatch,
every ancestor is charged, original deadlines hold, and unknown outcomes never
restore capacity. A retried request with the same id answers the original
admission instead of charging twice. Revoking a child grant stops that child and
every descendant immediately and cannot be undone by reissuing the grant. A
child verifies the hash-chained history itself and stops if the parent's history
is rolled back or rewritten, so a restart cannot return spent capacity.

The user chooses where a run's ledger lives: served by the parent locally, or by
Astrolift as a managed service (Astrolift placement follows separately). See the
[protocol](../delegation-ledger.md).

Also in this release: Ctrl+C in the terminal cancels the active turn and waits
for cleanup; a second press within two seconds exits (#403).

Refs: [#415](https://github.com/calliopeai/calliope-cli/issues/415).
